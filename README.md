# 事事通校园配送系统联网版

这是独立于当前单机稳定版的新联网版雏形，第一阶段只做洗护业务。

## 当前已包含

- Supabase 员工登录
- Excel 导入订单
- 后台录入已核销的抖音团购订单
- 自动生成订单、物品、水洗标
- 配送员取件任务
- 工厂连续识别二维码、Code-128条形码或扫码枪输入，整批确认入库、出库
- 出库后自动生成送回任务
- 地址识别规则与异常修正
- 学生输入手机号查询进度

## Supabase 初始化

1. 创建 Supabase 项目。
2. 打开 SQL Editor。
3. 完整执行 `supabase-schema.sql`。
4. 到 Authentication 创建员工账号。
5. 到 Table Editor 的 `profiles` 表新增员工资料：

| 字段 | 示例 |
| --- | --- |
| id | 选择 Authentication 用户的 id |
| name | 张三 |
| phone | 15599157072 |
| role | admin / courier / factory |

## 水洗标首次编号

发布前，在当前业务库（`bjlimqtrkdokmjpdcraa`）执行 `supabase-wash-label-first-issue-migration.sql`。
导入同一取件日期的全部订单并核对楼栋后，再首次导出。系统按学校、校区、楼栋的顺序分配正式条码。全新日期从 `001` 开始，同日补录从已有最大号续编。合并打印时各取件日期分别编号，补打使用已分配的条码。

## 水洗标打印批次

发布前，在当前业务库（`bjlimqtrkdokmjpdcraa`）执行 `supabase-wash-label-print-batches-migration.sql`。

在「水洗标管理」勾选这次要打印的水洗标，点击「新建打印批次并导出」。同一个打印日按北京时间自动记录第 1 批、第 2 批等。待编号的水洗标按学校、校区、楼栋排序，同一条码日期接着已有最大号续编。Excel 的序号与条码日期后的编号一致。

第二次打印时可以点「全选待编号」，也可以手动勾选。要重印某一批，在已保存的打印批次中选择该批并点击「补打整批」，系统按原顺序导出、使用原条码和最新联系电话。

## 订单管理搜索

发布 build 96 前，在当前业务库（`bjlimqtrkdokmjpdcraa`）执行更新后的 `supabase-admin-order-search-migration.sql`。后台筛选超时天数时，按距订单上次更新的时长计算，每满 24 小时算 1 天，并继续使用每页 50 单的分页搜索。

## 列表操作与加载优化

build 97 改订单状态后只更新对应行，显示「已保存」即可退出。当前筛选列表保留行位置，重新筛选或打开页面时读取最新结果。

build 98 水洗标搜索覆盖全部历史批次，列表每页显示 50 个。输入稍停 220 毫秒后更新结果，切换批次复用已加载的数据。翻页保留勾选和未保存的品类编辑，全选、批量保存和导出覆盖完整筛选结果。首次进入页面仍读取历史水洗标，查询只取业务所需字段，后续页面最多同时读取两页。

后台刷新只加载当前后台栏目和统计，不再加载隐藏的配送员、工厂列表。各端复用自然排序比较器，减少楼栋排序的计算。以上前端优化无需数据库迁移。

## 异常工单按客户归组

build 99 的处理中、已结案工单分别按联系电话归组，同一客户的不同订单集中显示。电话号码统一识别空格、横线和大陆手机号的国家区号；缺少电话时仅合并同一订单的工单。客户组沿用首张工单的处理优先级，处理中紧急工单优先，组内按紧急程度和提交时间排列。搜索会隐藏没有匹配工单的客户组，并显示每组匹配的工单数量。每张工单仍单独处理，无需数据库迁移。

## 工单筛选、认领与用户名登录

build 100 支持按待客服、待客户、处理中、已解决、已关闭筛选，并可切换「我的工单」。筛选与搜索组合使用，刷新工单后保留筛选条件。每张工单显示负责人，未分配工单可以认领，或在修改处理状态时自动认领到当前账号；已有负责人继续保留，结案后也可在「我的工单」查询。认领及状态修改会核对原负责人、状态、更新时间，遇到并发修改时刷新核对。

员工登录支持邮箱和用户名。用户名按小写映射至 `用户名@staff.shitong.invalid`，在当前业务库 Supabase Authentication 创建对应邮箱账号，再配置 `profiles` 角色。`xiaoshi` 对应 `xiaoshi@staff.shitong.invalid`，管理员资料名称为 `xiaoshi`。内部邮箱不接收邮件，账号密码通过 Auth 管理，前端不保存账号密码。筛选、认领复用既有 `assignee_id` 字段，无需数据库结构迁移。

## 抖音团购后台录单

发布前，在当前业务库（`bjlimqtrkdokmjpdcraa`）执行 `supabase-manual-wash-order-migration.sql`。

管理员先在抖音核销，再从「后台工作台」或「订单管理」打开「新增抖音团购订单」。填写券码、实付金额、联系人、地址、取件日期和物品。保存后创建待取件订单和取件任务，每双鞋或每件衣物对应一个待编号的水洗标。同一券码只能录入一次，正式条码随同一取件日期的其他水洗标在首次导出时统一分配。

## 工厂连续扫码

1. 选择“连续入库”或“连续出库”。
2. 系统自动打开后置摄像头。
3. 每识别一个水洗标就立即处理，摄像头保持开启。
4. 入库只接受“已取件”物品；出库只接受“已入厂”或“清洗中”物品。
5. 页面显示本轮数量、最近记录，并允许撤销上一单。

## 地址识别规则

规则只在导入 Excel 时使用。系统会在“表单信息 + 收货地址”中查找关键词，命中后自动填写规则对应的学校、校区和楼栋。

- 例如：`花溪校区17栋` → `师大 / 东区 / 17栋`
- 规则不会修改已经导入的订单。
- 已有订单请在“异常修正”中处理。
- “保存修正”只修改当前订单；“保存并记住规则”会修正当前订单，并保存一条供以后导入使用的规则。
