# 事事通校园配送系统体验审查

## 审查步骤

1. 登录前后台首页：页面可正常加载，但 Supabase 配置、员工登录和业务入口同时出现，首屏职责混杂。
2. 员工登录与后台工作台：登录和数据加载正常；后台能看到订单、物品和业务入口，但导航层级较多。
3. 学生独立查询页：入口简洁、客服信息清楚；当前仅凭手机号即可匿名查询，存在隐私与滥用风险。

## 优先建议

1. 立即收紧学生查询：改为“手机号 + 订单号”或短信验证码，只返回脱敏后的必要字段，并增加限流。
2. 按角色收紧 Supabase RLS：配送员只访问分配给自己的任务，工厂员工只访问入库/出库所需字段。
3. 把 Supabase 配置移入管理员专属设置页，普通员工和学生不需要看到连接参数。
4. 重做后台首页指标：突出待处理事项、异常订单、今日取送和积压数量，而不是只显示总量。
5. 改善表单和反馈：增加可见标签、字段级错误、加载状态、离线/数据库暂停提示和成功提示。
6. 调整 PWA 缓存策略：HTML 与脚本优先检查新版本，并提供“发现新版本，立即刷新”的提示。

## 证据限制

- 已验证登录、后台首屏和学生公开查询入口。
- 未执行订单导入、批量修改、工厂扫码、配送确认等会写入真实业务数据的操作。
- 截图只能支持可见界面判断，完整无障碍结论仍需键盘和读屏测试。
